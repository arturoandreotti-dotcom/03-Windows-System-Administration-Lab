# Windows Event Logs Investigation

## Objective

Investigate Windows Event Logs using PowerShell to identify system errors, analyze warnings, and troubleshoot potential issues in a Windows 11 virtual machine.

## Lab Environment

| Component | Configuration |
|---|---|
| Operating System | Windows 11 Enterprise Evaluation |
| Hypervisor | Oracle VirtualBox |
| Administrator Account | LabAdmin |
| Remote Access | Remote Desktop Protocol (RDP) |
| Management Tool | PowerShell |

## Event Log Overview

The following Windows Event Logs were examined:

- **System:** Windows services, drivers, and operating system events.
- **Application:** Events generated by installed applications.
- **Security:** Security auditing events.

### PowerShell Command

```powershell
Get-WinEvent -ListLog System, Application, Security |
    Select-Object LogName, RecordCount, IsEnabled
```

### Results

| Log | Record Count | Enabled |
|---|---:|---|
| System | 2,023 | True |
| Application | 769 | True |
| Security | 22,054 | True |

All three event logs were enabled and contained recorded events.

**Note:** Record counts represent a snapshot of the VM during the investigation and may change over time.

## System Error Investigation

### Objective

Identify recent Windows System errors and determine whether they represent ongoing problems.

### Retrieve Recent Errors

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = "System"
    Level = 2
} -MaxEvents 5 |
    Format-List TimeCreated, Id, LevelDisplayName, ProviderName, Message
```

### Results

The following errors were identified:

| Event ID | Provider | Description |
|---|---|---|
| 7022 | Service Control Manager | Delivery Optimization service hung during startup |
| 7011 | Service Control Manager | UmRdpService response timeout |
| 1040 | Microsoft-Windows-TPM-WMI | TPM attestation health check failed |
| 46 | volmgr | Crash dump initialization failed |
| 24641 | Microsoft-Windows-BitLocker-Driver | BitLocker volume master key retrieval error |

### Service Investigation

Events `7022` and `7011` were investigated further because they involved Windows services.

The current service states were checked using:

```powershell
Get-Service -Name DoSvc, UmRdpService |
    Select-Object Name, DisplayName, Status, StartType |
    Format-Table -AutoSize
```

**Results:**

| Service | Status | Startup Type |
|---|---|---|
| Delivery Optimization (DoSvc) | Running | Automatic |
| Remote Desktop Services UserMode Port Redirector (UmRdpService) | Running | Manual |

Additional Event Log queries identified:

- One recorded occurrence of Event ID `7022`.
- Two recorded occurrences of Event ID `7011`.

### Findings

Both services were running when inspected, despite the earlier errors.

The RDP connection and clipboard functionality were also tested successfully after the investigation.

No service configuration changes were necessary.

**Conclusion:** Historical service errors should be correlated with current service status and observable symptoms before corrective action is taken.

## Shutdown and Startup Investigation

### Objective

Investigate unexpected Windows shutdown events and correlate them with system startup records.

### Retrieve Shutdown Events

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = "System"
    Id = 41, 6008, 1074
} |
    Select-Object TimeCreated, Id, ProviderName, Message |
    Format-List
```

### Event ID Analysis

| Event ID | Provider | Meaning |
|---|---|---|
| 41 | Kernel-Power | Windows restarted without completing a clean shutdown |
| 6008 | EventLog | The previous shutdown was unexpected |
| 1074 | User32 | A user or process initiated a shutdown or restart |
| 12 | Kernel-General | The operating system started |

The investigation identified multiple unexpected shutdown records on November 6, 2026.

Event ID `1074` also showed legitimate restart requests initiated by Windows components, including `StartMenuExperienceHost`, `winlogon`, and `TrustedInstaller`.

### Check the Last Boot Time

```powershell
Get-CimInstance Win32_OperatingSystem |
    Select-Object LastBootUpTime
```

**Observed result:**

```text
LastBootUpTime
--------------
11/06/2026 23:09:06
```

However, the latest Event ID `12` indicated a system startup at approximately `21:43:15`.

The timestamps did not match.

### Investigate Time Synchronization

Further examination of Kernel-General Event ID `1` identified a system clock adjustment associated with `VBoxService.exe`.

The adjustment was approximately 5,150,904 milliseconds (about 85 minutes and 51 seconds).

This occurred after the host laptop had been closed and subsequently resumed.

### Findings

- Multiple unexpected shutdown events were recorded.
- Some restart events were explicitly initiated by Windows processes.
- The reported last boot time differed from the latest observed startup event.
- VirtualBox Guest Additions (`VBoxService.exe`) performed a significant clock adjustment.

**Conclusion:** Event Log timestamps should be interpreted carefully in virtualized environments, especially when host suspension and guest clock synchronization may affect the timeline.

The available evidence suggests that time synchronization contributed to the timestamp discrepancy, but does not conclusively establish the cause.
